# 可视化深度研究工作区设计规格

## 目标

把深度研究从“长篇 Markdown 编辑器”升级为可快速判断、可深入阅读、可追溯证据的研究工作区。GitHub 项目、arXiv 论文与 Hugging Face 技术内容使用不同的研究解释框架，并在完整报告中提供一张可渲染的综述图。

## 用户结果

- 深度研究页中部首先显示研究摘要、关键判断、局限与证据指标，不再默认展示整篇源码。
- 右侧显示排版后的完整研究报告，包含 Mermaid 一图综述。
- 用户仍可切换到 Markdown 编辑模式并保存人工修订版本。
- GitHub、arXiv、Hugging Face 的报告章节与研究问题不同，而不是把平台名填入同一模板。
- 旧版研究报告继续可读；摘要层对旧标题做兼容提取。

## 信息架构

### 共享开篇

1. `研究摘要`：结论先行，说明“它是什么、核心价值、最重要判断、适用边界”。
2. `一图综述`：恰好一个 Mermaid `flowchart`，最多 10 个节点，并附图示证据说明。
3. `研究范围与证据质量`：说明纳入、排除、缺失材料与结论置信边界。

### GitHub 项目模板

围绕项目定位、差异化、系统架构、模块边界、关键流程、实现机制、工程质量、依赖、可复现性、采用建议、局限与未验证假设、研究启发与关联方向形成工程研究报告。

### arXiv 论文模板

围绕研究问题、论文主张、方法原理、关键创新、算法流程、实验协议、结果与消融、结论有效范围、开放问题、相关工作脉络与复现建议形成论文研究报告。

### Hugging Face 技术内容模板

围绕内容定位、目标读者、核心观点、技术路线、产品或训练机制、工件与配置、案例与证据强度、代码/论文/模型/数据关系、适用场景、信息缺口与延伸方向形成技术内容研究报告。

## 版式与交互

- 中部“深度研究”标签页默认进入“研究速览”。顶部是来源类型与一句话摘要，随后是四张研究判断卡：问题/价值、关键贡献或结果、局限、启发。
- 中部工具栏提供“编辑完整报告 / 返回研究速览”，只有编辑模式显示保存按钮和 Markdown 文本域。
- 右侧标题在研究报告激活时改为“完整研究报告”，并持续显示渲染后的全文。
- 标签管理移动到研究内容之后，避免打断“状态 → 摘要”的阅读链路。
- 窄屏沿用现有底部预览入口；研究速览仍留在主工作区。

## Mermaid 安全边界

- 后端要求恰好一个 `mermaid` 围栏代码块，只允许 `flowchart` 或 `graph` 开头。
- 拒绝 Mermaid init 指令、`click`、HTML 标签与 `javascript:`。
- 前端按需加载 Mermaid，使用 `securityLevel: strict`、禁用自动启动和 HTML 标签。
- 渲染失败时回退为可复制的源码，不阻塞完整报告阅读。
- 普通 Markdown 继续禁用原始 HTML、远程图片和非 HTTPS 链接。

## 证据与兼容性

- 三类模板都有固定章节顺序；除图示、范围、标签和证据索引外，研究性正文每个非空段落必须引用已纳入的 `[E<n>]`。
- 摘要与结论同样必须有证据，避免把无依据判断放在最显眼位置。
- 已保存的旧报告不重新校验；前端用旧标题回退生成速览。重新运行研究后产出新模板。

## 验收标准

- 三种平台分别生成并验证各自的精确模板。
- 缺少 Mermaid、包含危险 Mermaid 指令、标题顺序错误、未知引用或正文缺少引用时，报告重试后如仍失败则诚实失败。
- 研究标签页默认不显示长文本域，能看到摘要与至少三个研究判断。
- 切换编辑模式后可保存；右侧始终显示完整报告并正确渲染 Mermaid。
- Mermaid 为独立懒加载产物，不进入主入口包。
- 后端、前端测试和生产构建通过，部署后使用真实 GitHub 项目完成一次端到端研究。
